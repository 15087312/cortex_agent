# 专利交底（简明版）

**发明名称**：一种基于探针间接激活与认知黑板的多模型分层协作方法及系统

---

## 1. 一句话说明

让多个大模型像公司一样分工干活：**总指挥接需求 → 交给主管拆解 → 主管派给专家执行 → 结果统一汇总回总指挥**。三个关键新做法：模型之间不直接互相调用（通过"探针"间接激活）、所有中间状态集中放在一面"认知黑板"上、上下文分两层刷新（省 token）。

## 2. 解决什么问题

现有多 AI 协作技术四个毛病：

1. 主模型直接调用子模型，代码写死、换模型就要改代码，还容易出安全漏洞；
2. 为了让模型"知道全局情况"，每次调工具都把全部上下文重新发给模型，又贵又慢；
3. 各个模型自己记自己的账，状态对不上，回复重复；
4. 任务层层转包后，没法查"这个结果是谁委托谁做出来的"。

## 3. 怎么做的（核心方法）

### 机制一：探针间接激活——模型不直接调用模型

顺序是固定的四步：

```
模型 → 调用工具（delegate_task）→ 生成探针（Probe）→ 探针激活下级模型
```

- 上级模型只说"我要委托谁做什么"，具体"拉起下级模型"的事由探针完成；
- 探针会带上：目标角色身份（人设/专长/可用工具）、发起方、结果回传给谁、超时；
- 好处：不管下级模型是哪家公司什么接口（OpenAI/Anthropic/Gemini/本地 Ollama），一律同一套协议协作；所有"激活"动作都经过同一个口子，方便统一做安全审批；
- 主管和专家可以同时派多个，N 主管 × M 专家并行干活。

### 机制二：认知黑板——所有模型的"唯一记事板"

- 所有任务、中间结果、发现，都写到一块共享黑板上，每个模型只从黑板上"按职位取自己该看的那一页"（按层级切片视图）；
- **每个用户回合黑板完全换新**——上一次任务留下的推理过程不会污染这一次的回答（防止答非所问/重复回复）；
- 委托会留下完整的"转包记录"：谁委托的、父任务是什么、根任务是什么，层层委托能顺着记录查回去（委托树）。

### 机制三：两层循环——全局感知和干活连续性分开

- **外层（思考轮，低频）**：接到新任务或被下属唤醒时，重新组装完整上下文（黑板状态 + 长期记忆 + 感知事件），让模型看清全局；
- **内层（工具循环，高频）**：一轮之内连续调工具时，结果直接追加到对话流，不重建上下文；
- 好处：全局刷新只发生在"情况真变了"的时候，token 消耗不随工具调用次数翻倍。

## 4. 一张图（执行流程）

```
用户输入
   ↓
总指挥（Large）：看黑板切片 + 记忆 → 决定怎么拆任务的层
   ↓ 委托
主管×N（Supervisor）：领域拆解 → 派专家
   ↓ 委托
专家×M（Expert）：实际执行（查资料/写代码/操作屏幕…）
   ↓ 结果写上黑板
总指挥被唤醒 → 读全局发现 → 整合成最终答复 → 给用户
```

## 5. 和现有技术的区别（一句话版）

| 现有做法 | 本方案 |
|---|---|
| 模型 A 直接函数调用模型 B | 只能通过"工具→探针"间接激活，统一权限口 |
| 每次工具调用都重发全局上下文 | 两层循环，只在世界变了时重建 |
| 各模型私有状态，容易打架 | 唯一黑板 + 按层级切片 + 每回合隔离 |
| 层层转包无法追溯 | 委托树结构化落黑板，可查链 |

## 6. 准建议的权利要求主线（草）

1. **方法权**：模型通过工具指令发起委托 → 探针装载角色配置并激活下级 → 下级结果作为"专家发现"写黑板 → 上级被唤醒后按切片视图整合；
   特征：每次委托形成含父/子/根任务标识的结构化记录，构成可追溯委托树。
2. **从属权**：双层循环的重建时机；黑板每回合隔离；探针激活统一过安全门控。
3. **装置权 / 权介质权**：对应系统与介质。
