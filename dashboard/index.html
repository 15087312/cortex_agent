✦ 01 · Core capabilities

Beyond retrieval

Cortex's trinity memory system lets AI do more than recall — it traces causality, isolates context per agent, and learns incrementally from every interaction.

Hybrid retrieval: vector + keyword + causal graph

Every query fans out across three engines in parallel. FAISS handles semantic similarity (cosine on 384-dim L2-normalized embeddings), SQLite JSON matching covers keyword precision, and the causal graph expands through BFS neighborhood diffusion. Results merge through a 5-factor score — semantic weight 0.35, importance 0.20, recency 0.20, utility 0.15, frequency 0.10 — then normalize, threshold, and rank.

Causal reasoning: from correlation to causation

When a query contains intent markers like "why", "root cause", or "predict", the DepthRecallScheduler activates — anchoring on causal graph nodes, then drilling down via CausalTree (trace_up for溯源, trace_down for prediction, bidirectional for generalization). Each traversal produces chains of cause-effect with configurable depth (default 2, max 4). Edge confidence updates incrementally on every recall.

Multi-agent memory isolation

Not all agents see the same past. The owner_id field partitions memory by model role: large_primary and large_coder access the full pool; supervisor and expert agents see only their own events. This enables collaborative multi-agent architectures where memory scope matches authority — without data leakage or context pollution.

Incremental learning & graceful degradation

Every retrieval updates the causal graph — confidence boosts on traversed paths, new nodes auto-created for discovered factors, events linked to anchors. If FAISS is unavailable, the system falls back to keyword-only search. If the embedding model fails, a background worker retries later. If the LLM is down for reduction, rule-based fallback kicks in. No single point of failure.

✦ 02 · Retrieval pipeline

From conversation to context

Every user session flows through five stages — extraction, embedding, hybrid search, deep recall, and context injection — in under 200ms at p50.

Memory extraction

The EventReducer calls an LLM with a structured prompt to extract MemoryEvent objects — each carrying a fact (≤500 chars), thought (≤500), lesson (≤300), importance score, keywords, and type. Causal nodes and edges are extracted simultaneously.

LLM-driven · JSON extraction

Vector encoding & storage

Each event is encoded into a 384-dim L2-normalized vector via paraphrase-multilingual-MiniLM-L12-v2 (mean pooling, max length 128). Vectors are stored in a FAISS IndexFlatIP index on disk alongside SQLite for structured fields.

SentenceTransformer · FAISS · SQLite

Hybrid search & scoring

Three parallel searches (FAISS cosine, SQLite keywords, causal graph BFS) produce candidate sets. The 5-factor formula scores and normalizes across the batch; results below 0.2 semantic similarity are discarded. Top K are returned ranked.

0.35·sem + 0.20·imp + 0.20·rec + 0.15·util + 0.10·freq

Deep causal recall

If intent classification detects logic keywords or shallow confidence is below 0.3, the DepthRecallScheduler triggers — anchoring on causal graph nodes, then tracing up (溯源), down (prediction), or bidirectionally (generalization) with intent-weighted scoring.

CausalTree · intent classification

Context injection

Results are formatted as a 「历史记忆」 block and injected into the LLM's context window. The ContinuousThinker calls retrieve() on every turn; the Conscience system generates inner monologue from retrieved events and causal expansions.
